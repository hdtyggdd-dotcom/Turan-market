For always-available phone access, the owner accepted a published browser version rather than requiring an always-running Expo Go development session. Keep the Expo Go preview available for development; this decision does not abandon native development.

**Why:** The owner needs access outside active Replit sessions and explicitly approved browser-based access.

**How to apply:** Keep the published browser entry as the actual marketplace, not an Expo Go instruction page. Do not describe a workspace preview as a permanent link; permanent access requires a successful publication and a verified production URL.

Distinguish fixes in the workspace from fixes delivered to customers.

**Why:** The owner reported missing product photos again after successful preview checks; the published app was still serving an older build. An existing photo could be fetched successfully while the old listing screen did not display it.

**How to apply:** For repeated reports, first identify whether the user is on the published site, Replit/Expo preview or an installed Android build. Verify that the affected channel includes the fix before declaring the customer's issue resolved. Offer Publish for a stale website; an installed APK requires an updated native build, not just workspace edits.
